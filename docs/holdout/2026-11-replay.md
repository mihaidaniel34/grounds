# Hold-out replay, November 2026: what an agent is told after each commit

grounds 0.0.12 (master at `2ee631e`; no Rust has changed since the
[second hold-out measurement](2026-11b.md) ran at `acb4c3a`), run the way it
is built to be used, after a change: `grounds changed --base <parent>` at real
main-line commits of the 40 projects of [corpus/holdout.tsv](../../corpus/holdout.tsv),
which the rules were never tuned on. The two hold-out reports measured
whole-project runs (`grounds check`) and found the compile-break and wiring
rules wrong almost every time they fired (298 of 313 false, then 224 of 224).
This report asks whether that carries over to the per-edit mode, where a gap
in the model is there before and after a change alike. **It measures only.**
No rule, fixture or line of Rust was changed because of it.

## Headline

1. **Break reports at main-line commits: 0.** 514 commits replayed on all 40
   projects (272 on the first set, 242 on the second); no compile-break
   finding on a changed line and no place in another file reported as broken,
   so 0 false, on 0 of the 40 projects and 0 of the 514 commits. No DI finding
   (`bean-not-found` and the rest) on a changed line either. 406 of the 514
   commits changed a declaration, so there was something to report breaks
   against; a planted break (a renamed `JsonWriter.isLenient` in gson) is
   reported with its 5 broken callers.
2. **Commits where an agent would have been told something false: 30 of 514
   (5.8%).** 43 commits (8.4%) got any finding at all: 25 only false ones,
   13 only true ones, 5 both. All 30 are told something false by a bug,
   style or security rule, none by a compile or wiring rule.
3. **Precision of the changed-line findings: 22 true of 73 (30.1%).** There
   were only 73 findings at `--min-severity warning`, fewer than the 150 the
   plan asked for, so every one was judged instead of a sample. Warnings: 20
   true, 48 false (29.4%). Errors: 2 true of 5 (both `trust-all-certificates`
   in powerjob; the 3 false ones are `trust-all-certificates` twice in
   tsunami and `compareto-specific-value` once). No verdict was unclear.

Findings per commit, all 514: median 0, 90th percentile 0, maximum 9 (one
omnifaces commit). Over the 43 commits that got any: median 1.

Reproduce: fetch each project of corpus/holdout.tsv at its pinned commit with
`git fetch --depth 61` and add `[classpath]\nscan_caches = false` as
`grounds.toml`, then

    python3 -I scripts/replay.py DIR --grounds target/release/grounds --commits 15 --budget 420 --out P.json
    python3 -I scripts/replay_findings.py DIR --from P.json --out P.findings.json
    python3 -I scripts/replay_findings.py --summary *.findings.json
    python3 -I scripts/replay_findings.py --sample 150 --seed 1 *.findings.json

Every verdict is in [2026-11-replay.tsv](2026-11-replay.tsv) (rule, severity,
project, commit, path, line, verdict, reason, permalink), with a reason for
true verdicts too. Three replays were run concurrently on a 4-core machine.

## False break reports

None. There was nothing to group by cause.

What can be said about why: the 246 compile-break and wiring findings that a
whole-project run of the same binary makes on these projects (table below)
come from framework features the model lacks, and those features are in the
code before a commit as much as after it. 18 of the 246 sit in files that a
replayed commit edited (maven `AbstractSession.java` 4, pig 7 in two
`*ServiceImpl.java`, mall4j 7 in four). None was reported on a changed line
and none came back as a place the commit broke, which is what a differential
report should do with a gap that was there before the commit. Two limits on that: a commit that edits the very line
of such a finding would still get it (changed-line findings are not compared
with the parent), and no replayed commit added new code using a feature the
model lacks (a new `@QueueBean` factory on kestra, a new Lombok builder
field access). Kestra, the project with 151 of the 246, got only 5 commits
replayed in the time budget (a rerun got 10, also without a break report).
