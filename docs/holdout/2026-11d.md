# Hold-out precision, November 2026 (fourth set)

*This section was written and committed before grounds was run on any of
these projects and before any finding was looked at. The measurement
follows in later commits.*

## How the fourth set was chosen

The first three sets of [corpus/holdout.tsv](../../corpus/holdout.tsv) are
spent. The third ([2026-11c](2026-11c.md)) left three preview rules that were
right every time they were judged but had too few findings to judge:
`narrowing-compound-assignment` (3 findings on that set),
`log-placeholder-mismatch` (13) and `assertj-assertion-without-check` (11).
This fourth set is twice as large, 40 projects, and is picked so that those
three rules get findings. The rules for choosing it:

- **Fresh.** No project is in corpus/projects.tsv, corpus/smoke.tsv or the
  first three sets of corpus/holdout.tsv (checked by owner/name and by
  repository name), and none is a fork (GitHub's `fork` flag was checked for
  every one) or a copy of one of them.
- **Aimed at the three rules.**
  - For `assertj-assertion-without-check`: projects whose tests use AssertJ
    a lot (debezium, spring-integration, spring-data-mongodb,
    spring-session, Strata, reactor-core, reactor-netty, redisson,
    testcontainers, java-operator-sdk, parquet-java, ta4j, XChange,
    prometheus client_java, JsonPath, aircompressor, rocketmq).
  - For `log-placeholder-mismatch`: projects that log heavily through SLF4J
    or Log4j 2 (bisq, debezium, jmeter, openhab-core, shenyu, killbill,
    bookkeeper, xchange, parquet-java, hivemq, canal, ratis, terasology).
  - For `narrowing-compound-assignment`: numeric code, namely codecs
    (aircompressor, jackson-dataformats-binary, commons-imaging, parquet-java,
    bitcoinj), parsers and databases (questdb, JsonPath, canal's binlog
    reader), game engines and servers (Minestom, Terasology, Geyser), maths
    and geometry (commons-math, jts, RoaringBitmap, joda-time) and finance
    (Strata, ta4j, killbill, bisq, XChange).
- **The same mix as before otherwise**: 25 Maven and 15 Gradle builds; from
  about 19,000 to 2.9 million lines; plain libraries, plain Spring
  libraries, Spring Boot applications (shenyu, canal), Micronaut
  (micronaut-kafka), Guice applications (hivemq, bisq, killbill), an OSGi
  platform (openhab-core), desktop applications (jmeter, bisq), and heavy
  Lombok users (xchange, bisq, bookkeeper, testcontainers, geyser).
- **Alive**: every one was pushed to in 2026, all but JsonPath (February)
  and canal (July) within the last month; each is pinned to the head of its
  default branch on 2026-11-11.
- Chosen from what the author knew of the Java ecosystem. After the
  checkouts were fetched, only the counts in the table below were taken
  (files, lines, and files importing AssertJ, an SLF4J or Log4j 2 logger, or
  Lombok); they changed nothing in the list. No project will be dropped or
  added after a run.

"Files importing AssertJ" counts `.java` files with an `import` (static or
not) of `org.assertj`; "files with an SLF4J/Log4j 2 logger" counts files
importing `org.slf4j.Logger` or `org.apache.logging.log4j.Logger`, or a Lombok
`@Slf4j`/`@Log4j2`; lines are all lines of all `.java` files, tests included.

All 40: 64,123 Java files, 12,135,930 lines. questdb alone is 2.9 million
lines (24%); its findings could dominate a rule, as maven's and kestra's
did in the first two sets. Where a target rule has more than 60 findings,
the 60 judged are drawn round-robin over projects (as holdout.py samples),
so that no project fills the sample.

Considered and rejected:

- **hipparchus-math/hipparchus**: began as a fork of Apache Commons Math and
  still shares much of its code; commons-math was taken, so one of the two.
- **apache/flink-cdc**: keeps patched copies of Debezium source files in its
  tree, and debezium is in the set (Flink itself is in corpus/smoke.tsv).
- **spring-projects/spring-authorization-server**: its code moved into
  Spring Security (corpus/smoke.tsv).
- **apache/pulsar, hazelcast/hazelcast, apache/iotdb**: very large; one very
  large project (questdb) is enough, and the logging-heavy distributed
  systems are represented by bookkeeper, ratis and rocketmq.
- **CS-SI/Orekit**: maths-heavy, but built on Hipparchus and very large;
  commons-math and jts cover numeric libraries.
- **square/okhttp, square/okio**: mostly Kotlin now.
- **OpenGamma/Strata**: taken under its current owner,
  tradingtechnologies/Strata (the old URL redirects).

## Method (to be followed)

As [scripts/holdout.py](../../scripts/holdout.py) does for the earlier sets:
shallow fetch of the pinned commit, `[classpath] scan_caches = false` in a
`grounds.toml` where there is none, no build and no jars, a release build of
master, `grounds check --format json`.

- The three target rules: every finding is judged, up to 60 per rule; above
  60, a seeded sample of 60 (`--seed 1`), said so in the results.
- Every other preview rule of severity warning or error with findings: a
  seeded sample of 8 (`--sample 8 --seed 1`), as the earlier reports did.
- Every verdict has a reason, true ones included, in
  [2026-11d.tsv](2026-11d.tsv). Where it is cheap, a verdict is confirmed with
  a small synthetic reproducer compiled and run with javac/java (never
  project code).
- Nothing found here is turned into a fixture or a test, and no product code
  is changed by this task.

Reproduce:

    python3 -I scripts/holdout.py --dir DIR --after 'fourth set, 2026-11'
    python3 -I scripts/holdout.py --dir DIR --after 'fourth set, 2026-11' --sample 8 --seed 1 \
        --all narrowing-compound-assignment,log-placeholder-mismatch,assertj-assertion-without-check --all-max 60
